# Локальный AI-агент для почты: сводка из трёх строк и срочное в Telegram без облака (Python + Ollama + Docker Compose)

Набор файлов к ролику «Локальный AI-агент разбирает входящую почту: сводка и срочное в Telegram без облака». Контейнер на вашем компьютере читает новые письма по IMAP, локальная модель (Ollama, qwen2.5:7b) пишет выжимку из трёх строк, срочное приходит в Telegram с кнопками «В работу», «В архив», «Спам». Без абонентской платы и без облачного помощника.

Канал с материалами: [@ByteAutomate_AI](https://t.me/ByteAutomate_AI). Настройка под вашу почту и команду: @konstantin_100.

```bash
git clone https://github.com/Kavilucky/ep32-local-mail-ai && cd ep32-local-mail-ai
```

## Что внутри
| Файл | Для чего |
|---|---|
| `docker-compose.yml` | два контейнера: `ollama` (модель) и `mail_agent` (скрипт); порты наружу не публикуются; секреты через Docker secrets |
| `mail_summarizer.py` | комментированный скрипт: IMAP, запрос к Ollama, Telegram, кнопки; только стандартная библиотека Python |
| `Инструкция.txt` | та же инструкция простым текстом, включая получение пароля приложения |

## Как это устроено
1. `mail_agent` раз в две минуты заходит в ящик по IMAP и берёт новые письма. Читает заголовок (От, Тема) и первые 1500 символов тела: `BODY.PEEK` не ставит метку «прочитано», письма остаются на сервере.
2. `ollama` с моделью `qwen2.5:7b` возвращает JSON: срочность (`urgent`, `normal`, `spam`) и выжимку из трёх строк. Слова «срок», «оплата», «счёт», «договор» всегда поднимают письмо в срочные (правило поверх модели).
3. Срочное приходит в Telegram (`sendMessage`) с inline-кнопками. «В работу» ставит флаг, «В архив» и «Спам» копируют письмо в папку и убирают из входящих (безвозвратного удаления нет). Нажатия принимаются только от вашего `TG_CHAT_ID`.
4. Обычные письма можно собирать в дайджест (`DIGEST_HOUR`), спам не показывается.

```
почта (IMAP) ──► mail_agent ──► ollama (qwen2.5:7b) ──► выжимка + срочность
                     │
                     └──► Telegram: сводка и кнопки ──► IMAP: флаг / архив / спам
```
Тело письма остаётся на вашем компьютере. **Короткая сводка проходит через серверы Telegram**: для закрытых отправителей используйте `SKIP_SENDERS`.

## Запуск по шагам
1. Бот: у @BotFather команда `/newbot`, сохраните токен; узнайте свой `chat_id` (напишите боту и откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`). Токен никому не показывайте.
2. Пароль приложения почты (не основной пароль): Gmail, Яндекс Почта и Mail.ru выдают его в настройках безопасности; IMAP должен быть включён.
3. Создайте файлы секретов (по одному значению в файле, без кавычек): `secrets/imap_password.txt` и `secrets/tg_bot_token.txt`.
4. Создайте `.env` рядом с `docker-compose.yml`:
   ```
   IMAP_HOST=imap.gmail.com
   IMAP_USER=ваш_адрес@example.com
   TG_CHAT_ID=ваш_chat_id
   ARCHIVE_FOLDER=Archive
   SPAM_FOLDER=Junk
   ```
   Имена папок у сервисов разные (Archive, Архив, Spam, Спам): впишите точные.
5. Запуск: `docker compose up -d`, затем модель (несколько ГБ, один раз): `docker compose exec ollama ollama pull qwen2.5:7b`.
6. Проверка: `docker compose exec mail_agent python mail_summarizer.py --demo` (тестовое письмо через модель), `--test` (сообщение в Telegram), логи: `docker compose logs -f mail_agent`.

## Безопасность
- Пароль приложения и токен бота только в `secrets/*.txt` (файлы в `.gitignore`), не в yaml и не в переменных окружения. Если файл мог утечь, отзовите пароль приложения в почте, токен отзовите у @BotFather.
- Текст письма передаётся модели как данные: команды из письма модель не выполняет, действия с почтой идут только по вашим кнопкам. Это снижает риск, но не отменяет его.
- Порты контейнеров наружу не публикуются.

## Резервная копия (обязательно)
Конфиг (`docker-compose.yml`, `.env`, скрипт) и секреты храните по правилу **3-2-1**: три копии, два носителя, одна вне дома или на внешнем диске. Оригиналы не удалять, пока копия не проверена. Секреты в облако без шифрования не класть.

## Честные ограничения
- Скрипт и `docker-compose.yml` написаны по документации и **на живой почте, с настоящей Ollama и ботом автором не запускались**; `docker compose` не проверялся. Первый запуск на тестовом ящике.
- Для сжатой модели нужно от 8 ГБ оперативной памяти (ориентир, замерьте `docker stats`); на процессоре письмо обрабатывается секунды или десятки секунд.
- Модель иногда ошибается в срочности и выжимке: срочное проверяйте глазами. Возможны лишние тревоги из-за слов-триггеров.
- Читаются заголовок и первые 1500 символов; вложения не разбираются.
- Образ `ollama/ollama:latest` лучше закрепить на конкретную версию после проверки; интерфейсы почты и условия сервисов меняются.
- «Без подписки» значит без абонентской платы за этот набор: вы используете свой компьютер, электричество и свою почту.
- Цифры из ролика («сорок писем», «два часа») ориентиры автора, не замеры.
