ЧТО ДЕЛАЕТ НАБОР
Агент работает у вас дома в контейнере Docker. Раз в две минуты он заходит в почту по IMAP, читает заголовок и первые строки новых писем, просит локальную модель (Ollama, qwen2.5:7b) определить срочность и написать выжимку из трёх строк. Срочное приходит в Telegram с тремя кнопками: «В работу», «В архив», «Спам». Работает без подписки и без облачного помощника: тело письма не покидает ваш компьютер.

ЧТО В НАБОРЕ
- docker-compose.yml: два контейнера, Ollama (модель) и агент (скрипт). Порты наружу не открываются.
- mail_summarizer.py: комментированный скрипт (IMAP, запрос к Ollama, Telegram, кнопки).
- Инструкция.txt: этот файл.

ЧТО ПОНАДОБИТСЯ
1. Компьютер или мини-ПК с Docker и Docker Compose (Windows, Linux или macOS). Оперативной памяти от 8 ГБ для сжатой модели qwen2.5:7b, лучше 16 ГБ; свободного места на диске около 10 ГБ. Без видеокарты модель работает на процессоре, письмо обрабатывается секунды или десятки секунд.
2. Почтовый ящик с включённым IMAP и ПАРОЛЕМ ПРИЛОЖЕНИЯ (не основным паролем).
3. Бот в Telegram: токен у @BotFather и ваш chat_id.

ПАРОЛЬ ПРИЛОЖЕНИЯ: КАК ПОЛУЧИТЬ
Это отдельный пароль, который почтовый сервис даёт одной программе. Его можно отозвать, не меняя основной пароль.
- Gmail: включите двухэтапную проверку в аккаунте Google, затем раздел «Пароли приложений», создайте пароль для «Почта». IMAP: imap.gmail.com.
- Яндекс Почта: Настройки, Почтовые программы, включить «С сервера imap.yandex.ru по протоколу IMAP» и создать пароль приложения в Яндекс ID.
- Mail.ru: Настройки, Безопасность, «Пароли для внешних приложений». IMAP: imap.mail.ru.
Названия разделов у сервисов меняются, сверяйтесь со справкой своей почты.

КАК ЗАПУСТИТЬ: ШАГ ЗА ШАГОМ
Шаг 1. Создайте бота у @BotFather командой /newbot и сохраните токен. Напишите боту любое сообщение, затем откройте в браузере адрес с вашим токеном: https://api.telegram.org/bot<ТОКЕН>/getUpdates и найдите число chat id. Токен никому не показывайте.
Шаг 2. Положите docker-compose.yml и mail_summarizer.py в одну папку. Внутри создайте папки secrets и data.
Шаг 3. Секреты: создайте два текстовых файла с одной строкой в каждом, без кавычек.
  secrets/imap_password.txt  (пароль приложения почты)
  secrets/tg_bot_token.txt   (токен бота)
Файлы никуда не публикуйте и не отправляйте в git.
Шаг 4. Создайте файл .env рядом с docker-compose.yml:
  IMAP_HOST=imap.gmail.com
  IMAP_USER=ваш_адрес@example.com
  TG_CHAT_ID=ваш_chat_id
  ARCHIVE_FOLDER=Archive
  SPAM_FOLDER=Junk
Названия папок у почтовых сервисов разные (Archive, Архив, Spam, Спам): откройте почту и впишите точные имена.
Шаг 5. Запустите: docker compose up -d
Шаг 6. Один раз скачайте модель (несколько ГБ): docker compose exec ollama ollama pull qwen2.5:7b
Шаг 7. Проверьте: docker compose exec mail_agent python mail_summarizer.py --demo (тестовое письмо через модель) и docker compose exec mail_agent python mail_summarizer.py --test (тестовое сообщение в Telegram).
Шаг 8. Отправьте себе письмо про оплату до пятницы. Через пару минут должно прийти сообщение с тремя кнопками. Логи: docker compose logs -f mail_agent.

КАК РАБОТАЮТ КНОПКИ
- «В работу» ставит флаг на письмо в почте, письмо остаётся во «Входящих».
- «В архив» и «Спам» копируют письмо в указанную папку и убирают из входящих. Копия остаётся в папке, безвозвратного удаления нет.
- Нажатия принимаются только от вашего chat_id.

БЕЗОПАСНОСТЬ
- Пароль приложения, а не основной пароль. Хранится только в secrets/imap_password.txt. Если файл мог утечь, отзовите пароль приложения в почте.
- Токен бота при подозрении на утечку отзовите у @BotFather.
- Письмо читается без пометки «прочитано», на сервере письма остаются.
- Текст письма внутри запроса к модели помечен как данные: команды из письма модель не выполняет, а действия с почтой происходят только по вашим кнопкам. Это защита, а не гарантия: модель может ошибаться.
- Сводка проходит через серверы Telegram. Для самых закрытых писем (юридические, медицинские) добавьте отправителей в SKIP_SENDERS в файле .env: такие письма агент пропускает.

ВТОРАЯ КОПИЯ
Конфиг (docker-compose.yml, .env, скрипт) и секреты храните в двух местах (схема 3-2-1): копия на внешнем диске, оригиналы не удалять, пока копия не проверена. Файлы секретов в облачное хранилище без шифрования не кладите.

ЧЕСТНЫЕ ОГРАНИЧЕНИЯ
- Скрипт и docker-compose.yml написаны по документации и автором на живой почте и с живым ботом не запускались. Первый запуск на тестовом ящике.
- Для сжатой модели нужно от 8 ГБ оперативной памяти: это ориентир, замерьте на своём компьютере (docker stats). Скорость зависит от процессора.
- Модель иногда ошибается в срочности и в выжимке, особенно на длинных и сложных письмах: срочное проверяйте глазами. Слова «срок», «оплата», «счёт», «договор» всегда поднимают письмо в срочные: возможны лишние тревоги.
- Читаются заголовок и первые 1500 символов тела. Вложения не разбираются.
- Образ ollama/ollama:latest лучше закрепить на конкретную версию после проверки; условия сервисов и интерфейсы почты меняются: проверяйте актуальные условия.
- «Без подписки» значит без абонентской платы за этот набор: вы используете свой компьютер, электричество и свою почту.
- Цифры из ролика («сорок писем», «два часа») ориентиры автора, не замеры.
